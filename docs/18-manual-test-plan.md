## 2. 随时回退（先看这条，心里有底）

```fish
for f in main.js manifest.json styles.css
    curl -fsSL -o $PLUGIN/$f https://github.com/ArtemisLin/obsidian-wechat-diary/releases/download/0.4.0/$f
end
```

然后重载 Obsidian。（`gh` 也行：`gh release download 0.4.0 --repo ArtemisLin/obsidian-wechat-diary -D $PLUGIN --clobber`）

回退后会发生什么，**先说清楚**：
- 你的**设置在**：`data.json` 里 `settings.diaryFolder` / `pathFormat` / 附件 / 提醒 / 剪藏都还在
  （新版的"设置垫片"是**可枚举**的，就是为了让值照旧写回 `data.json`）。
- 顶层 `ilink` / `profile` / `session` 三个键**没了**（这是设计：它们搬进了 `accounts[0]`）。
  0.4.0 启动时会走"从密钥存储恢复身份"那条路（v0.2.1 修的那个机制），**绑定能自己回来**。
- ⚠️ **如果你在测试版里重新扫过码**，回退后 0.4.0 可能拿到的是旧 token（新码只写
  `...-bot-token:a1` 这个带后缀的 key），那样需要**重新扫码一次**。
  想免除这点的话说一声，我可以加一条"账户 #1 同时把 token 镜像写进旧 key"（约 5 行 + 用例）。
- `profile.name`（称呼）与 `session` 里的计数在回退后会丢（0.4.0 不认识 `accounts`）。不回退就没事。

## 5. 自动测覆盖不到、这次重点看的地方

这些已被"故意改错看用例挂不挂"的变异验证确认过**没有自动兜底**（详见设计稿 §9.2）：

1. **行内文件夹选择器的同树拒绝**（把它改坏，739 条用例全过）→ 对应上面 **D1/D2**
2. **账户列表渲染 + 点行切换**：点标题能切、点输入框**不会**重画（打字不丢焦点）
3. **添加账户 → 立刻扫码 → 写进新槽**（B1/B2）；到第 6 个账户应被上限拦住
4. **重新扫码写回原槽**（E3）
5. **删除的二次确认** 与"vault 文件一个没动"（E1）
6. **手改 data.json 造同树的警告时机**（D4）
7. **多账户时的行高与滚动位置**

## 6. 出问题时给我什么

1. 截图（含那条 Notice 的完整文字）
2. 控制台里 `[wechat-diary]` 的**整段**文本（不是摘要）
3. `data.json` —— **先把隐私字段删掉再发**：`accounts[].ilink.botTokenFallback`、`accounts[].ilink.contextTokens`、
   `accounts[].ilink.baseUrl`。（**bot token 与 绑定身份不在这个文件里**，它们在 Obsidian 密钥存储中，放心。）
4. 你做了什么 → 期望什么 → 实际什么（三句话就行）
